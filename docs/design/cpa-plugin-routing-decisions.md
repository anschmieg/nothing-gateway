# CPA plugin and smart-routing decisions

Research checkpoint: **November 23, 2026**. This supersedes the runtime assumptions, not the historical record, in the [recap](cpa-plugins-and-smart-routing-recap.md), [evaluation plan](gateway-plugin-evaluation-plan.md), and [saved references](gateway-plugin-reference-backlog.md). The matrix records dispositions, not enabled features. See [source receipts](cpa-plugin-source-receipts.md) for exact revisions.

## Request, assumptions, and evaluation order

- **Requested:** establish what native CPA or a plugin can replace; investigate every named routing, quota, provider, and protocol candidate; keep Copilot Auto as Auto only; prefer eligible OpenAI organization grants without mixing non-Codex project keys with Codex OAuth; keep Coolify and automate CPA/CPAMC updates with verification and rollback. Preserve billing limits, caller isolation, and upstream access boundaries. No deployment, production credentials, or live inference in this turn.
- **Prior recommendations, not requirements:** shadow the Codex usage observer first; use a mapper for special aliases; favor grants from a manual snapshot; install proactive refresh if native refresh is inadequate; use a Worker for lightweight routes. None implies approval to enroll an account, alter routing, or load an unreviewed binary.
- **Active baseline:** [README](../../README.md), [migration inventory](cpa-first-repository-migration.md), and [Coolify runbook](../../deploy/cli-proxy-api/COOLIFY.md) describe one patched native CPA runtime. The former Node gateway plus embedded CPA `v7.3.20` is historical. Copilot Auto, SystemOne and specialist Mistral/realtime paths from that stack are ports, not active code that can be removed. The local-model controller is separate. The README's deferred findings are not reopened.
- **Evidence standard:** **S** = exact source/config inspection; **T** = isolated synthetic test (current results below and earlier results explicitly marked); **E?** = actual account eligibility not verified; **P?** = live state not verified. A public release, Git commit, mock success, model ID or official product feature is not account or deployment evidence. No third-party candidate was installed or executed. Start with ownership and release parity, then credentials/quota and cost signals, then provider and protocol experiments.

## Staged implementation and release gates

Stage 1 passed locally. Stage 2 has a [tag-triggered candidate workflow](../../.github/workflows/runtime-release.yml), [daily upstream discovery](../../.github/workflows/runtime-upstream.yml), and a rebased Gemini overlay on the reviewed CPA line. The remaining Stage 2 gates are the CPA `v8.1.2` port, a hosted build-only run and dated candidate publication, and a promotion rehearsal with the installed plugin set and a compatible copy of config/state. See the [release runbook](../../deploy/cli-proxy-api/COOLIFY.md#tag-triggered-candidate-releases).

1. **Now — baseline candidate parity.** Rebuild the known upstream `v8.0.49` patch chain in scratch, run tagged plugin tests and the canonical loopback smoke. Make the first bounded increment a release-gate regression: an explicit `PAID` grant cannot transfer across caller keys sharing the same session ID or across sessions of the same key; blocked requests send zero upstream generation calls. Keep existing positives for discovery, exact dispatch, SSE/429, compact, cache-field preservation, and caller-bound opaque state. Run stock latest only as a plugin protocol comparison, not a substitute for the patched policy. Rollback: revert fixture-only change; no runtime behavior changes.
2. **Next — port and automate verification.** On upstream stable release events or scheduled discovery, resolve immutable source commits and verified archive/plugin digests; stage a clean patch rebase, pinned toolchains/lockfiles and a signed or checksummed manifest (CPA/CPAMC/plugins/patchset/config schema). Fail closed on changed patch anchors. Run focused Go policy, plugin ABI, synthetic budget/cooldown/refresh and canonical smoke checks; build CPAMC with frozen dependencies and run Access/login/plugin-resource checks (and write-only key display). Gate promotion on failures, not on tag freshness. Require a tested artifact pair, one owned restart with the Coolify runtime lock, previous pair retained, state/config compatibility or private migration rollback, and non-inference health/management checks. Separate candidate automation from authorized promotion; no stock auto-update for mounted artifacts. Runtime still tracks repo `main`/`HEAD`; runbook, not this checkout, describes verifying the actual Coolify setting and trigger on an authorized release.
3. **Then — observing, not changing routing.** Compare native and shadow usage on synthetic fixtures first; record cache/uncached input, output, tool charges, route/auth and terminal outcome once per attempt. For quota, compare a trace for both cross-provider and eligible credential picks; no stale/unknown promotion. For grants, use fake clock and fresh per-grant snapshots scoped to the key's org; reserve conservative upper bounds atomically across keys/in-flight requests before hypothetical dispatch, settle exactly once against verified usage/rates, reconcile spend and out-of-band usage without double subtracting, and use headroom for reporting lag. Reserve uncached price unless the discount is assured; missing rates, uncertain billable partials, unknown fees, stale/depleted/expired balances and restart ambiguity must not create preference or silently allow PAYGO. Simulate overlap/expiry, 429/cancel after billable work, multiple keys, external spend and restarts. A future credit-backed selector must enforce this ceiling and require distinct explicit PAYGO opt-in when grants cannot cover the request. Do not change current `PAID` semantics in shadow. Rollback by discarding proposals and leaving base routing intact.
4. **Finally — isolated provider/protocol increments.** Owner approves one access path and the protocol acceptance check from the matrix, one plugin at a time. Begin with an official Auto SDK contract check or a real format gap reproducible in mocks, not the largest provider bundle. No live account or production validation until independently authorized. Remove obsolete code only after equivalent control/protocol behavior and a working rollback are demonstrated.

### Release blockers for expanded behavior

- **Responses response IDs are not opaque reasoning tokens.** At `v0.3.0`, `executor.go` verifies caller scope for observed opaque tokens, but forwards `previous_response_id` unchanged. The existing positive fixture even sends a synthetic ID not issued in that session. This is not evidence that sharing an upstream project key isolates stored continuations. Smallest gate: mock a stored response from caller A; independently opt A and B into `PAID` on the same project; A can continue it, B's continuation is rejected before any upstream POST. Include credential/project changes and restart in a follow-up if binding is persisted. Until scoped ownership is demonstrated, do not expand shared-project stateful routing or expose ID-based endpoints. No claim about a live route or an actual disclosure.
- **An estimated grant ledger cannot guarantee no charge.** The [official benefit rules](https://developers.openai.com/api/docs/guides/chatgpt-api-credits) cover Responses and exclude Codex API-key usage; they also say purchased credits are used after eligible free credits are exhausted. A local cutoff cannot prevent a shared organization from consuming credit elsewhere. Make any promised no-PAYGO contract contingent on an independent enforceable upstream spend boundary; otherwise keep grants as a ranking signal under explicit paid-risk admission, not a verified FREE/SUB allowance.
